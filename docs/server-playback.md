# Серверные часы, общий буфер и восстановление комнат

Включение на одном процессе: `python3 infra/configure_room_recovery.py` в папке
проекта на сервере, затем установка новых API/web образов. Скрипт сохраняет
имеющийся ключ; новый Fernet-ключ генерируется только один раз в приватном `.env`.
Ключ необходимо хранить вместе с отдельной защищённой резервной копией данных.
Замена/утрата ключа делает старый файл восстановления нечитаемым.

`SERVER_PLAYBACK_ENABLED=true` включает серверное управление доступным полным
аудио YouTube, SoundCloud и VK. Яндекс получает прямой URL прежним способом.
Spotify/Apple остаются личными Embed/MusicKit либо ранее реализованной передачей
звука вкладки Spotify. Серверного извлечения защищённого аудио этих сервисов нет.
Доступность аудио конкретного провайдера всё ещё зависит от авторизации и региона.

Сервер хранит часы текущего элемента и сам переключает очередь по длительности.
Main отправляет только явный `playback_control` (`play`, `pause`, `seek`) с ID
элемента и актуальной ревизией; его `playback_sync` в серверном режиме игнорируется.
Случайная пауза, сворачивание и отключение Main не останавливают других слушателей.
Если все отключились, часы приостанавливаются. Опустевшая начавшаяся комната
хранится 15 минут, включая комнату с одним хостом. Новая неоткрытая — 30 секунд.
Переключение и голоса используют прежнюю очередь; Spotify WebRTC-пары не меняются.

Main и подключённые слушатели получают общий дескриптор только текущего/следующего
элемента через разные права доступа. YouTube и progressive SoundCloud/VK передаются
диапазонами 256 KiB; HLS-сегменты — целиком с ограничением размера. Одновременные
запросы одинакового фрагмента объединяются в один запрос к источнику. LRU/TTL-буфер
не больше 64 MiB на процесс, максимум 32 ожидающих загрузки и 4 активных загрузки;
временные буферы активных загрузок учитываются отдельно. На SSD аудио не пишется.
Это общий буфер VOD и серверные часы, а не серверное микширование в новый аудиофайл.
Браузеры декодируют поток и выполняют переход. При переходе между серверными
источниками следующий начинает отсчёт с 3 секунд с учётом перекрытия. Клиент без
готовой предзагрузки может начать с этого места без кроссфейда. Задержки сети и
запрет autoplay на отдельном устройстве остаются возможны; они локальны.

`ROOM_STATE_FILE=/app/state/rooms.enc` расположен в именованном Docker volume.
Файл шифруется Fernet, атомарно заменяется с fsync, права 0600. Сохранение после
изменений с интервалом около секунды и при штатной остановке. Потеря последней
секунды изменений при жёстком сбое возможна. Файл содержит комнаты, очередь,
голоса, роли/идентификаторы и время; максимум 32 MiB JSON до шифрования. Ошибка
записи логируется без содержимого; повреждённый файл/неверный ключ не заменяется
молча пустым состоянием. Живые WS, listener-токены, TURN credentials и токены
музыкальных аккаунтов не сохраняются. После рестарта комната доступна по старому
ID, воспроизведение восстанавливается на паузе; музыкальные аккаунты при истёкшем
серверном handle нужно подключить заново. Очередь и названия сохраняются.

Проверки: восстановление зашифрованного файла, срок комнат, целостность/права,
серверные команды, игнорирование локальной паузы, отключение Main, автоматический
следующий трек и приватный доступ слушателя; общий буфер проверен на 12 одновременных
читателях с одним запросом на фрагмент и корректными Range. В браузере тестовый
WAV продолжился у гостя после закрытия хоста и сменился на следующий элемент.
Реальные внешние потоки и длительный прогон на телефонах проверяются отдельно.
